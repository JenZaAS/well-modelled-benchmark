# Results

`python -m benchmark.run` writes scores and prediction files here, one folder per contender:
`results/<contender>/<dataset>/<target>/<scenario>[/<test>]/`. The viewer's Benchmark tab reads them.

This folder is shared through git so everyone sees the same scoreboard on their own laptop. Only the files
on the allowlist in the repo's `.gitignore` are shared; everything else here stays local.

| File | Contents | Shared through git |
|---|---|---|
| `scores.json` | Metrics, timings, model hash, git commit, machine | Yes, every dataset |
| `runs/<timestamp>_<dataset>.json` | All scores from one run | Yes, every dataset |
| `summary/*.md`, `summary/*.json` | Tables from `python -m benchmark.scoreboard --write` | Yes |
| `predictions.json` / `predictions.npz` | Per test well: depth, measured target, GR/CALI/RDEP, p05/p50/p95 | Only `force2020` and `synthetic` |
| Anything else (`runs/*.csv`, `failure.json`, `blue_ml_study/`, ...) | | No |

## Why prediction files are restricted

A prediction file contains measured well curves, so committing one republishes part of the dataset, and this
repo is public. FORCE 2020 is open data that may be redistributed with credit (see below), and `synthetic` is
generated by this repo (`src/wmb/synthetic.py`). Predictions for NLOG, Kansas KGS, Volve, Diskos or any other
dataset stay on your laptop: colleagues see your scores, and the viewer's curve plot asks them to re-run the
model.

To share predictions for another dataset, first check in [docs/data-licences.md](../docs/data-licences.md)
that its licence allows redistribution, then add its two lines (`predictions.json` and `predictions.npz`) to
the allowlist in `.gitignore` and its credit line below. Never add Diskos or company data.

## Sharing your results

1. Run the benchmark as usual. For runs you will push, `--predictions npz` holds the same content in a file
   about 3x smaller (writing one format removes the other).
2. `git status results` lists only files that are allowed to be shared. Commit the ones for **your own
   contenders**, so two people never write the same file. For shared baselines such as `template_linear` and
   `red_floor_train_mean`, agree in the chat who pushes them.
3. `git pull --rebase`, then push. Colleagues `git pull` to see your runs in their viewer.
